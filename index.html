Projects

PyCheb: Chebfun in Python, built with AI coding agents

Chebfun represents smooth functions by their Chebyshev expansions, so you can differentiate, integrate, find roots and solve differential equations on functions as if they were numbers. It's about 3,400 MATLAB files. We're porting it to Python with AI coding agents (I work with Codex), and most of the engineering is in the process that makes an agent's output trustworthy.

  • Test-driven development. Chebfun's MATLAB test suite is translated to pytest first. An agent then implements each class against those tests, so "done" means it reproduces MATLAB's behavior.
  • Held-out tests. The agent implementing a module is graded on tests it didn't write. It can't pass by shaping the tests around its own code, so a green run actually means parity.
  • Dependency-ordered translation. I had the agent map the MATLAB classes into a dependency tree, then turn it into a file-by-file implementation order. Agents are told to stop and report when they reach a dependency that hasn't been translated yet.
  • Scoped context. Each prompt limits the agent to the module, its tests and its direct dependencies. That keeps token cost down and keeps edits from spreading.
  • Debugging test failures. When tests fail, I separate floating-point rounding differences from real bugs. I push back when an agent argues that a behavior gap is acceptable instead of fixing it.

Python, NumPy, pytest, Codex

Fast simulation of discrete-rank scheduling

A single-server queue that always serves the job with the lowest rank, where a job's rank depends on how much service it has already received. A naive discrete-event simulator has to stop at every rank breakpoint. Ours advances groups of tied jobs together and uses bisection to jump straight to the next event that actually changes which job is being served.

We then replaced the per-job Python loops with vectorized NumPy array operations. On the largest benchmark (5,000 jobs, highest rank resolution), the naive simulator took over 16,000 seconds, about four and a half hours. Ours finished in 150 seconds, a 108× speedup.

The shape of city shadows

Fall 2026, in progress

Stand somewhere on a street and look toward the sun. Whether you're in shade depends on the skyline in that direction, and the skyline is set by whichever building looks tallest from where you are, which is often not the tallest one.

βC(p, θ) = arctan maxj hj / dj(p, θ) VC(p, θ, α) = 𝟏[ α > βC(p, θ) ]

You're in sunlight when the sun's elevation α clears the skyline angle β.

To study this in a controlled way, we split a city into a west and an east group of buildings and scale their heights by two multipliers, a and b. Which group controls the skyline flips wherever a·A = b·B, so each location and direction cuts the (a, b) plane into regions.

We then treat the whole collection of skyline rules as a mathematical space and ask whether it's a manifold. On the learning side, a VAE compresses lists of skyline measurements down to two latent coordinates, and we compare what it learns against the geometry.
